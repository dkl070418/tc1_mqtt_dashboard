# 升级提示词：2.1.4 → 2.2.0（给运维智能体）

> 把下面整段复制给你的智能体即可。它只做"升级+验证+回滚准备"，不需要改代码。

---

## 任务

把一台已经在跑 **v2.1.4** 的 tc1_mqtt_dashboard 部署升级到 **v2.2.0**，升级后逐项验证，并保证随时能一行回滚。
**不要修改源码，不要改设备 MAC / IP / 密码，不要动你自己的其它容器。**

## 0. 先确认现状（别急着动）

```bash
cd <项目目录>                    # 就是有 docker-compose.yaml 的那个目录
docker compose ps               # 确认 backend / nginx 在跑
docker inspect --format '{{.Config.Image}}' $(docker compose ps -q backend)
docker inspect --format '{{.Config.Image}}' $(docker compose ps -q nginx)
# 期望两者 tag 都是 v2.1.4
```

## 1. 备份（三件套，缺一不可）

```bash
TS=$(date +%Y%m%d_%H%M%S)
cp docker-compose.yaml    docker-compose.yaml.bak_214_$TS
cp config.yaml            config.yaml.bak_214_$TS
cp metadata/device_config.json metadata/device_config.json.bak_214_$TS   # 路径按实际挂载点调整
```

## 2. 换镜像 tag（**两个都要改**）

```bash
sed -i 's|mqtt-mgr-backend:v2\.1\.4|mqtt-mgr-backend:v2.2.0|; s|mqtt-mgr-nginx:v2\.1\.4|mqtt-mgr-nginx:v2.2.0|' docker-compose.yaml
grep -n 'mqtt-mgr-' docker-compose.yaml      # 确认两个都变成 v2.2.0
```

## 3. 配置（这一步决定"新特性有没有生效"）

2.1.4 → 2.2.0 **只新增两个键**，其余键不变（`scheduler_catchup_minutes` 等 2.1.4 就有）：

| 键 | 缺省行为 | 建议 |
|---|---|---|
| `v1_backend_scheduling` | 不写 = `false` | 想让 **v1（原厂固件）排插的定时任务改由服务器执行** → 必须显式写 `true` |
| `v1_time_sync_interval_hours` | 不写 = 6 小时 | 可写 `0` 关掉（V1 原厂固件会忽略 `setting.time`，这功能对 v1 实际无效，留着只会多日志） |

```bash
# 需要 v1 后端调度就加这一行（幂等）
grep -q '^v1_backend_scheduling:' config.yaml || echo 'v1_backend_scheduling: true' >> config.yaml
# 可选：关掉对 v1 无效的周期校时
grep -q '^v1_time_sync_interval_hours:' config.yaml || echo 'v1_time_sync_interval_hours: 0' >> config.yaml
```

docker compose pull backend nginx
docker compose up -d backend nginx
docker compose ps                 # 两个容器 Up，镜像 tag 为 v2.2.0

## 5. 验证清单（逐条打勾，别只看"容器 Up"）

```bash
# ① 启动日志：三行状态必须能对上你的配置
docker logs mqtt-mgr-backend 2>&1 | grep -E '\[scheduler\]|\[timesync\]|服务启动'
#   期望看到：
#   [scheduler] 定时调度器已启动 (仅对 firmware=v2 的设备生效), 错过补发窗口=30 分钟
#   [scheduler] V1 后端调度已启用 / 未启用(...)      <- 与 v1_backend_scheduling 一致
#   [timesync] V1 固件周期校时已启用/已关闭          <- 与 v1_time_sync_interval_hours 一致

# ② 站点存活
curl -s -o /dev/null -w '%{http_code}\n' http://<你的地址>/api/ping        # 200

# ③ 前端版本号（浏览器强刷 Ctrl+F5 后页脚应显示 v2.2.0）
docker exec $(docker compose ps -q nginx) sh -c "grep -o 'v2\.2\.0' /usr/share/nginx/html/assets/App-*.js | head -1"

# ④ 功耗采集恢复（有 V2 固件设备时）
docker logs mqtt-mgr-backend 2>&1 | grep -E 'power/state' | tail -3
#   期望看到 "已订阅 homeassistant/sensor/<MAC大写>/power/state"

# ⑤ 管理员接口（可选，需要 token）
curl -s -H "Authorization: Bearer <token>" http://<你的地址>/api/admin/power/summary?mac=<设备MAC>
#   应同时出现 today_energy_kwh / month_energy_kwh（以及 v2 设备的 device_today_kwh）
```

## 6. 升级后必须做的两件事（否则"新特性看起来没生效"）

1. **v1 任务要逐条改执行位置**：2.2.0 起是"每个任务"决定谁执行（`exec` 字段）。
   2.1.4 时代建的任务没有这个字段 → **仍由排插自己执行**。
   要改成服务器执行：网页 → 该插口"定时" → 编辑任务 → **执行位置选"服务器"** → 保存。
   （保存时会把设备侧同名槽位写 `on=0` 防双触发，安卓 App 里该任务会显示为"关闭"——这是预期行为。）
2. **强刷前端**（Ctrl+F5），否则浏览器还在用旧的 JS。

## 7. 已知坑（**别做这些**）

- ❌ **不要一次改一堆任务后立刻观察接管结果**：后端接管按"每 15 秒最多 10 条"分批进行（防止命令连发刷爆排插的小接收缓冲），任务多时要等几分钟。
- ❌ **不要把"任务多、命令密"当成可以随便压测**：v1 原厂固件 MQTT 接收缓冲很小，历史上"整包超 2KB → 截断 → 看门狗复位"，表现是排插闪断重启。
- ❌ **不要指望升级后 V2 设备的"今日/本月用电"立刻准**：芯片故障期间没有功率上报，历史无法补；从升级时刻起才开始真实采集，次日才完整。
- ❌ **不要在 v1 设备上试图"删除"任务并期望设备里没有**：固件没有删除命令，只能 `on=0` 停用，设备上会留一条停用记录（安卓 App 里可见）。
- ❌ **不要改 `frontend/vite.config.js`**：那是开发用代理，生产镜像里不用它。
- ⚠️ 如果这台机器同时跑着别的 dpanel/compose 栈，改 tag 只改本项目的 compose，别动别人的。

## 8. 回滚（一行）

```bash
sed -i 's|mqtt-mgr-backend:v2\.2\.0|mqtt-mgr-backend:v2.1.4|; s|mqtt-mgr-nginx:v2\.2\.0|mqtt-mgr-nginx:v2.1.4|' docker-compose.yaml
docker compose pull backend nginx && docker compose up -d backend nginx
# 或者直接还原备份：cp docker-compose.yaml.bak_214_$TS docker-compose.yaml
```

注意事项：

- 新配置键在 2.1.4 里会被 YAML 忽略，**不会报错**；
- 但如果你已经启用过 `v1_backend_scheduling`（设备侧任务被写了 `on=0`），回滚到 2.1.4 后那些任务**不会执行**，
  需要在网页里重新保存一次任务，把配置写回设备。

## 9. 验收通过的标准（全中才算成功）

| 项 | 期望 |
|---|---|
| 容器 | backend / nginx 都是 `v2.2.0`、状态 Up |
| 启动日志 | 三条状态行与你配置一致（无 error） |
| 站点 | `/api/ping` = 200 |
| 前端 | 页脚版本号 v2.2.0；插口卡片"定时"徽标进页面就有数字 |
| 任务 | 网页"定时"面板能看到设备上真实任务（含手机 App 建的） |
| 功耗 | V2 设备曲线连续（约 2 秒一个点）；V1 设备数字与曲线正常 |
| 设备 | 排插没有异常重启（uptime 连续、日志无反复重连） |

有任何一项不符合，先按第 8 节回滚，再把 `docker logs mqtt-mgr-backend --since 10m` 的报错贴出来。
